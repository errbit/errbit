# Errbit Internationalization

## Catalogs

Errbit-owned UI catalogs live in `config/locales/<locale>.yml`. A selectable
catalog must:

- Use the locale identifier as both its filename and its top-level YAML key.
- Define a non-empty `<locale>.locale_name` autonym.
- Preserve interpolation variables and pluralization shapes from `en.yml`.

Missing translated UI values are allowed in a structurally valid catalog.

The application keeps `I18n.available_locales` broad because Rails and
`rails-i18n` provide framework data. The profile selector uses the separate
file-derived `Errbit::Locales.selectable` collection, so framework-only locales
are not offered to users.

## Runtime Behavior

For HTML requests, locale selection is:

1. An available explicit user locale.
2. The best supported `Accept-Language` value.
3. English.

`nil` on `User#locale` means Automatic. API and notifier requests skip locale
negotiation and always respond in English. Locale state is scoped to the
request and is restored afterward.

Development and test deliberately raise when a translation is missing from the
active locale. This makes incomplete catalogs visible while developing. The
production environment enables English fallback for missing non-English UI
values. A missing English source key retains Rails' normal missing-translation
behavior in production.

API and notifier requests skip locale negotiation and always return English
responses. Their response messages are code-owned English constants and are not
part of the UI translation catalogs.
